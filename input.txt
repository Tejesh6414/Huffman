Information theory is the mathematical study of how data can be measured, stored and sent from one place to another. It was founded by Claude Shannon in 1948, and it gave engineers a precise way to talk about the amount of information in a message. The central idea is that a message carries more information when it is more surprising. A letter that appears very often tells us little, while a rare letter tells us a lot.

Entropy is the number that measures this average surprise. If a source produces symbols with probabilities p, then the entropy is the sum of p times the logarithm of one over p, taken in base two, and it is measured in bits per symbol. Entropy sets a hard limit. No lossless compression scheme can use fewer bits per symbol on average than the entropy of the source.

Huffman coding is a lossless data compression algorithm that comes very close to this limit. It assigns shorter binary codes to frequently occurring characters and longer codes to rare characters. The algorithm was invented by David Huffman in 1952 while he was a student, and it is still taught in almost every course on data structures and coding.

To build a Huffman code, we first count how many times each character appears in the text. Then we place every character in a priority queue, ordered by its count. We repeatedly remove the two characters with the smallest counts, join them under a new parent node, and put the parent back into the queue. When only one node remains, the tree is complete. Walking from the root to a leaf, we write a zero for every left branch and a one for every right branch, and the path to each leaf becomes the code for that character.

Because no code is the beginning of another code, the result is called a prefix code. This property means that a decoder can read the stream of bits from left to right and always know where one character ends and the next one begins. No separators are needed, and nothing is lost, so the original text can be recovered exactly.

The quality of a code is judged by its average length. We multiply the length of each code by the probability of its character and add up the results. The difference between this average length and the entropy is called the redundancy of the code. The efficiency is the entropy divided by the average length, and for a good Huffman code it is often above ninety percent.

Huffman coding has limits, however. It must use at least one whole bit for every symbol, even when a symbol is almost certain to appear. It also treats every character as independent, so it ignores the fact that real language has strong patterns. After the letters t and h, for example, the letter e is very likely to follow. A method that looks at the previous characters can predict the next one much better than a method that only looks at overall counts.

This is where machine learning enters the picture. A small neural network can be trained to read a few characters of context and predict the probability of every possible next character. If these probabilities are sharp, we can build a fresh Huffman code for every position, giving a short code to the character that the model expects. When the prediction is good, the average number of bits per character drops below that of a plain Huffman code.

There is a price to pay for this idea. The decoder must have the same trained model as the encoder, so the weights of the network have to be stored or sent as well. For a short file, the size of the model can be larger than the savings. For a very large file, or when many files share one model, the savings can be worth the cost. It is also important to test the model on text that it has not seen during training, because a network can easily memorize a small sample.

Modern compressors combine these ideas. They use context models to predict the next symbol and arithmetic coding to turn those predictions into bits, which removes the one bit minimum of Huffman coding. Large language models are, in a sense, extremely powerful predictors, and the better a model predicts text, the better it can compress that text. Compression and prediction are two sides of the same coin.

Practical systems such as the formats used for images, music and documents rely on these methods every day. Each time a web page is loaded or a photograph is shared, some form of entropy coding is working quietly in the background to save time, space and energy. Studying Huffman coding is therefore a good first step toward understanding how digital information is handled.
